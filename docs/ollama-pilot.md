# JEI optional Ollama pilot

This is a disabled-by-default experiment. Existing stock feeds, indicators, alerts and schedules do not change.

1. On a supported Windows PC, install Ollama from https://ollama.com/download/windows.
2. Install the local model with `ollama pull qwen3:4b`. Do not expose port 11434 externally. Disable Ollama cloud features and verify offline inference before permitting any restricted content.
3. Run `python jei_local_ai_router.py --probe` on that PC. A remote runner's loopback is not the user's PC.
4. Run `python jei_local_ai_router.py --self-test` to verify the routing policy.

Public research can be considered for local inference only when explicitly enabled and the model is present. Otherwise the decision points to the existing cloud pipeline; it does not launch that pipeline. Restricted or unclassified jobs are held, even if the health check succeeds. No holdings, bank records, credentials or prompts are transmitted by this pilot.

Next acceptance gates: separate local inference worker, strict request/response validation, opt-in public task queue, idempotent job IDs and leases, simulated disconnect/reconnect, retry limits, measured latency and model quality. Public cloud fallback must reuse existing schedules and must not double-send alerts. Finance ERP integration is a separate task; no accounting ledger writes or cloud fallback for private data. No paid services required by this pilot; usage limits on existing cloud services remain.

## Colab coordination
The pilot now accepts the existing coordination JSON as an advisory input. It selects a Colab candidate only for explicitly public, opt-in tasks when local is unavailable, the status is RECENT_HEARTBEAT with authenticated Drive heartbeat evidence, and the caller independently verifies freshness and task capability. RECENT_HEARTBEAT is the verified state enumeration from tools/jei_colab_coordination.py. The existing Colab worker supports only audit_observed_picks; it cannot perform LLM summaries without a separate worker. STALE, unknown or unsupported tasks preserve the existing cloud pipeline (which owns Actions fallback). No job is dispatched by the router. Next: wire the actual heartbeat verifier and worker capability registry; exercise handoff with unique job IDs and acknowledgements. Never keep free Colab sessions alive through artificial activity or bypass usage limits.

## Executable pilot
From the repository root, run `python -m tools.jei_hybrid_audit` for a deterministic public-data audit, or `python -m tools.jei_hybrid_audit --check-colab` for a current authorized Drive check using the existing environment configuration. Add `--local-ai` only on a machine where the local model is installed and offline use has been verified. The script submits only aggregate counts to the local model; its narrative is unverified and never changes the observed statistics. Failure or timeout retains the deterministic audit. It reports the existing Colab task/ack evidence and a candidate route, not a remote dispatch. CI runs the router and hybrid tests, including ten simulated switch cycles, and executes the public deterministic audit with no credentials. No production workflows or schedules are changed. A live Colab session, actual local inference, a cross-machine job lease/queue, and release acceptance remain separate gates.

## Local persistence and retry guard
With `--local-ai`, the CLI now defaults to a local SQLite job database at `audit-output/hybrid_jobs.sqlite3` (override with `--job-db`). The key binds the source bytes, model name and audit engine digest. Transactional claims prevent simultaneous workers on one machine from publishing duplicate results; a two-minute lease fences expired workers. Failures retry after 60 seconds, up to three claims per key; completed summaries can be reused after restarting the program when the local model is available. Only public audit aggregate summaries are stored. Do not place the SQLite file on Google Drive, a network share or synchronized folders; this is not a cross-machine lock or dispatch queue. No cloud fallback is initiated for the narrative itself. Deterministic audit continues even if the local job store is unavailable. Real model inference, remote-worker leases and live Colab validation still require separate acceptance.

## Local public-task pull worker
Run from the repository root: `python -m tools.jei_hybrid_worker`. This one-shot worker polls the existing public GitHub/Colab coordination manifest, fetches the public pick-validation snapshot, and requires an exact versioned task ID before execution. It rechecks both inputs after computation and writes immutable local per-task receipts, never a mutable latest pointer. Add `--local-ai` only after installing and verifying the offline model. Identical aggregate versions reuse the local summary even if publication metadata changes. No credentials, public inbound ports, external result uploads, or background scheduler installation. Use a local NTFS/POSIX filesystem for atomic receipt creation. A legacy manifest, changed snapshot or network interruption safely returns a retryable status instead of publishing a new result. Colab and Actions continue their existing independent deterministic audit; the local receipt is not an authenticated cloud acknowledgement or a distributed lease.
